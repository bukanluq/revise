  • The client (your browser) sends a request, for example “give me the page”.
  • The server (the ESP32-S3) sends back a response, such as a web page or data.
  • Both devices must be on the same Wi-Fi network. The server is found by its IP address, printed in the Serial Monitor.
  • This idea of connecting physical devices to the network is called the Internet of Things (IoT).
Theory 2

The Sensor and the Output Pin

DHT11 sensor

  • Measures temperature (0–50 °C, ±2 °C) and humidity (20–90 %, ±5 %).
  • Sends both values on one data wire as a digital signal.
  • Slow sensor: read it no more than once per second.
  • If a reading fails, the library returns NaN (“not a number”).

GPIO output

  • A GPIO pin is a programmable connection on the chip.
  • HIGH = 3.3 V (ON), LOW = 0 V (OFF).
  • An LED needs a resistor to limit current.
  • A relay lets the small 3.3 V signal switch a bigger device. Some relays switch on with LOW (“active low”).

Safety: never connect mains electricity (230 V) without teacher supervision. Use an LED for this lab.

Theory 3

Routes, JSON and Polling

A route is a web address on the server that triggers a piece of code.

JSON

A simple text format for data. Example from /data:

{"temp":28.0,"hum":65,"output":false}

Polling

The page runs JavaScript that asks /data every 2 seconds and updates the numbers. No page reload is needed.

Activity 2

Upgrade: The Smart Thermostat

The idea

Right now a human presses the button. In Activity 2 the ESP32-S3 decides by itself.

  • AUTO mode: output turns ON when temperature ≥ limit.
  • MANUAL mode: the buttons work as before.
  • The limit can be changed from the web page with − and + buttons.

Theory: hysteresis

If the output switched exactly at the limit, noisy readings would make it flicker ON/OFF rapidly, which damages relays and fans.

Solution: turn ON at the limit, but turn OFF only when the temperature falls 1 °C below it. This gap is called hysteresis.

Programming concepts

Variable (stores the mode and limit) · Condition (if / else if) · Function (runAuto()) · New routes (/mode, /thr).

Review

Check Your Understanding

1. In this project, which device is the server and which is the client?

The ESP32-S3 is the server; the browser on your phone or computer is the client.

2. Why do we read the DHT11 only every 2 seconds?

The DHT11 is a slow sensor and needs time between measurements; reading too fast gives errors.

3. What problem does hysteresis solve?

It stops the output from rapidly switching ON and OFF when the temperature hovers around the limit.

4. What does the route /thr?value=32 do?

It sets the temperature limit to 32 °C (the code keeps it between 0 and 50).
